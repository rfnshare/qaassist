# Security Foundation

- Never commit secrets, tokens, API keys, customer data, or real credentials.
- Use `.env.example` only for placeholders. Real `.env` files stay ignored.
- Do not store production LLM keys in the browser extension.
- Use backend-mediated LLM access for product architecture.
- Store future tokens encrypted server-side with least-privilege scopes.
- For local development, Azure DevOps PATs stay in the API server environment only and must never be entered into extension settings.
- Product setup should use Azure/Microsoft delegated auth later. The extension may show connection status, discovered projects, discovered team boards, and selected team board, but it must not collect secrets.
- Step 0012 discovery routes are read-only and must not print PATs, Authorization headers, private work item content, or customer data.
- Keep browser host permissions limited to needed Azure DevOps domains.
- Do not silently exfiltrate board, story, file, or evidence data.
- Do not persist raw board/story data by default.
- Future audit logs should avoid raw story content by default.
- All write-back actions require explicit user approval.
- AI analysis, board knowledge upload, Azure Test Plans creation, bug creation, comments, and repository changes remain inactive until explicit review and approval flows exist.
- Step 0013 board briefing is deterministic preview logic unless a future backend LLM adapter is explicitly configured. The extension must not store AI keys or call model providers directly.
- Step 0014 work item detail fetch is read-only and backend-mediated. The extension must not call Azure DevOps directly, collect PATs, store secrets, or log private story descriptions and acceptance criteria.
- Step 0015 Story requirement analysis is deterministic backend logic and does not call LLM providers. Future LLM-assisted analysis must remain backend-mediated, avoid extension-side AI keys, and require source labels plus user confirmation.
- Step 0016 Board Knowledge is metadata-only. The extension may store non-secret source metadata scoped to the selected team board, but it must not read file contents, upload file bytes, index content, or send board knowledge to an LLM.
- Step 0017 Board Knowledge extraction preview is backend-mediated and JSON-only. The extension may send manually pasted `.txt` or `.md` text for preview, but it must not automatically read selected file bytes, store full extracted text, index content, call LLM providers, or include extraction results in Story analysis yet.
- Step 0018 Story analysis may include only explicit user-selected board knowledge evidence. It must not automatically include all board knowledge, send full documents, call LLM providers, require PATs, persist extracted full text, or write back to Azure.
- Step 0019 test case drafts are deterministic preview output. They must not call LLM providers, create Azure Test Plans items, write back to Azure, persist drafts, or become final without QA approval.
- Step 0020 reviewed test cases are local/session review output only. Approval means ready for a future export flow, not Azure Test Plans creation. Review normalization must not require PATs, call Azure DevOps, call LLM providers, persist reviewed cases, or write back.
- Step 0021 Azure Test Plans readiness is preview-only. It may validate reviewed cases and non-secret target IDs, but it must not require PATs, call Azure DevOps, create Test Plans items, persist readiness results, or treat approval as final creation consent.
- Step 0022 Azure Test Plans creation must be backend-only and explicit. It may create only selected readiness candidates after final user confirmation, must never accept PATs in the request body, must not create plans/suites, must not update stories or bugs, and must return sanitized created/failed/skipped results.
- Step 0023 optional LLM provider access is backend-only and disabled by default. The extension must not collect or store AI keys. Provider status may expose only non-secret flags such as provider, model, and whether backend config exists. LLM-assisted output is suggestion-only, must not replace deterministic evidence, must not write back, and must require QA review.
